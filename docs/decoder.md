# デコーダ

AMBE+2 と AMBE+ のデコーダです(`decoder/`)。API は `include/blip25.h` と `include/mbelib.h` にあります。

## 構成

| ソース | 内容 |
|---|---|
| `src/b25_*.c` | blip25-vocoder(Rust)の AMBE+2 デコーダを、1 関数ずつ C に移植したもの。規則は [porting.md](porting.md) |
| `src/blip25.c` | API とフレーム形式の変換 |
| `src/mbelib_compat.c` | mbelib 1.3 と同じ名前と引数の関数 |
| `src/ambeplus*.c` | AMBE+ のデコーダ。合成には blip25 のエンジンを使う |

- AMBE+2 のデコーダは、blip25-vocoder 1.0 とビット一致します。`make test` で確かめられます。
- 移植は、2 の補数と算術右シフトの処理系を前提にしています(GCC、Clang、MSVC)。

## mbelib からの移行

`include/mbelib.h` を使い、`libmbe` の代わりに `libblip25.a` をリンクします。mbelib との違いは次のとおりです。

- デコーダの状態は `cur_mp` に入ります。ストリームごとに別の `mbe_parms` を使ってください。
- `prev_mp`、`prev_mp_enhanced`、`uvquality` は使いません。`w0`、`L`、`Vl` などの欄も埋めません。
- C0 で 4 ビットの誤りを検出したフレームは、補間に回します。

## AMBE+

| RATET | 関数 |
|---|---|
| 31 | `blip25_decode_ambeplus_r31` |
| 0 | `blip25_decode_ambeplus_r0` |
| 22 | `blip25_decode_ambeplus_r22` |
| 17 | `blip25_decode_ambeplus_r17` |
| 26 | `blip25_decode_ambeplus_r26` |

- AMBE+ のレートの仕様は公開されていません。フレームの形式は、チップで測った結果と、失効した DVSI の特許から割り出しました。
- 2400 bps の符号帳は mbelib の D-STAR 用と同じです。4000 bps の 40〜49 番と 66〜78 番のビットの符号帳は、実際の音声に当てはめた推定値です。4000 bps のチップとの差(2.03 dB)の大部分はここにあります。

### 特殊フレーム(ピッチ符号 b0 ≥ 120)

AMBE-3000R の復号器で測った扱いを、そのまま実装しています。2000 bps(RATET 31)の b0 は 6 ビットなので、偶数の値だけです。

| b0 | 扱い |
|---|---|
| 120〜123 | 普通の音声フレーム(とても低いピッチ) |
| 124 | 背景雑音フレーム。V/UV の欄は無視され、全帯域が無声になります。最後に受けた 1 フレームを、消失が続いたときの雑音に使います |
| 125、127 | 消失 |
| 126 | トーン。ただし、無効なトーン番号は消失 |

- **消失**:直前のフレームを 3 回繰り返し、4 回目から無音になります。背景雑音フレームを受けたことがあれば、無音の代わりにその雑音を鳴らします(デコーダを初期化するまで)。`BLIP25_LOST` で渡した消失も同じ扱いです。
- **トーン(RATET 31、22、17、26)**:トーン番号 I(8 ビット)と振幅 A(8 ビット)を持ちます。
  - I = 5〜122:I × 31.25 Hz の単一トーン
  - I = 128〜143:DTMF(1 4 7 * 2 5 8 0 3 6 9 # A B C D の順)
  - I = 144〜147:呼出音などの 2 周波トーン(350+440、440+480、480+620、350+490 Hz)
  - そのほかの I:消失
  - レベル(単一トーン、実効値):−86.8 + 0.354 A dBFS。2 周波トーンは各成分がこのレベルです。
  - 上位 3 ビットは、ビット 6〜8 の値 d から {4, 0, 1, 2, 3, 7, 6, 5}[d] で求めます。
- **トーン(RATET 0)**:AMBE-1000 の形式で、DTMF だけです。列がビット 6〜7、行がビット 8〜9、振幅 A がビット 10〜17 で、各成分のレベルは −32.5 + 24 A / 256 dBFS です。
- **ビット配置**(シリアル順):

  | | トーン番号の下位 5 ビット(t4..t0) | 振幅(上位から) |
  |---|---|---|
  | 2400 bps(RATET 22) | 9、41、42、10、11 | 12、13、14、15、16、43、44、17 |
  | 2000 bps(RATET 31) | 9、37、10、11、12 | 13、14、15、16、38、17、18、19 |
  | 4000 bps(RATET 17、26) | 9、56、57、10、11 | 12、13、14、15、16、58、59、17 |

- **チップとの差**:トーン、DTMF、消失の遷移は、フレームごとのレベル差の中央値 0.14〜0.38 dB で一致します(5 つのレートとも)。消失が続いたときの背景雑音のレベルは、フレームの内容によってチップと ±4 dB 程度(まれにそれ以上)ずれます。
- 合成には、エンジンの AMBE+2 用のトーン合成を使っています。

### ビット数の合わないチャネルパケット(RATET 26)

AMBE-3000R は、RATET 26 の復号器に 128 ビット以外のパケット(CHAND、CHAND4)を渡してもエラーを返さず、必ず音声を返します。ほかのレートとして読み替えることはしません。チップで確かめた動作は次のとおりです。

- 復号器は 128 ビット分のチャネルバッファを 1 つ持っています。パケットは、その先頭から min(L, 128) ビットだけを上書きします。残りには、前のパケットまでの内容が残ります。128 ビットを超えた分は捨てられます。
- バッファは 4 ビットの軟判定値で持っています。CHAND のビットは 0 と 15 として入ります。このため、CHAND4 で送った残りの部分は、その確からしさのまま次のフレームに引き継がれます。
- リセット(PKT_RESET)してもバッファは消えません。
- L が 16 の倍数でないとき(40、72 など)は、最後の 16 ビット語の残りに不定の値が入るようです。この場合はチップと一致しません。16 の倍数の L(48、80、96)や、128 を超える L(144、192)はビット単位で一致します。

`blip25_decode_ambeplus_r26_chand`(CHAND)と `blip25_decode_ambeplus_r26_chand4`(CHAND4)は、このバッファを再現しています。

- CHAND4 の値 v は、LLR 2v − 15 として誤り訂正に渡します。
- `blip25_decode_ambeplus_r26` は L = 128 の場合で、同じバッファを通ります。
- `blip25_init` はバッファを 0(どちらでもない)で初期化します。
- `decoder/ambe2wav in.bin out.wav --rate 26 --chand` は、フィールド ID(0x01 か 0x17)、ビット数、データの順に並んだパケットの列を読みます。

チップとの比較(長さを混ぜたストリーム、52 フレーム)では、パケットの列を 128 ビットの CHAND4 フレームの列に直したものと、チップの出力が全フレームで同一でした。ambe2-c の出力も同一でした。チップとのレベル差は、中央値 0.64 dB、最大 6.5 dB です。大きめの差は、短いパケットで中身が壊れたフレームで出ます。

### 伝送誤りと再開

チップで確かめた動作です。

- **誤り訂正**:K=7 の畳み込み符号の最尤復号です。メトリクスが同点のときは、後ろの前状態(最も古い入力ビットが 1 のほう)を選びます。
  - ambe2-c も同じ規則です。誤りを入れた 48 フレームで、チップと同じ復号結果になります(テスト `apfec26 ap_r26e`)。
  - RATET 22 も同じ規則です(20 フレーム中 18 で一致)。
- **CHAND4 の値**:4 ビットの値 v は、LLR 2v − 15 の線形のメトリクスと同じ結果になります(誤りを含む 40 フレームで全一致)。
- **訂正しきれない誤り**:チップは誤りを検出せず、音声を止めません。ランダムなビット列を 40 フレーム続けて送っても、誤り訂正が出したビットをそのまま合成します。ミュートも繰り返しもしません。
  - 1 フレームで 13 ビット以上訂正したときだけ、出力がごくわずかに変わります(レベル差 0.01 dB 未満)。ambe2-c はこれを再現していません。
  - 消失として扱いたいフレームは、`BLIP25_LOST` で渡してください。
- **リセット**:復号器の状態と背景雑音の記憶は、すべて初期化されます。リセット前の履歴が違っても、リセット後の出力は同一です。チャネルバッファだけは残ります(前節)。`blip25_init` はチャネルバッファも初期化します。

測定と当てはめのスクリプトは neural-ambe2 の `ambeplus/` にあります(特殊フレームは `probe_special.py`、`compare_special.py`、チャネル入力は `probe_input.py`)。
