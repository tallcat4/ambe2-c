# encoder — AMBE+2 2450 bps エンコーダ（純 C）

> このページのコマンドは `encoder/` ディレクトリで実行します。

AMBE-3000R（ThumbDV, rate 34 = 2450 bps, FEC なし）とビット互換のフレームを出す、このリポジトリのオリジナルの
エンコーダです。デコーダ([マニュアル](decoder.md)、blip25c)と対になっています。

- **品質**：日本語の ABX テスト（チップで復号した音どうしを比較）で、チップのエンコーダと聞き分けられませんでした
  （30 問中 18 問正解、p = 0.18）。
  - 聞き手が分かった数少ない手がかりは、チップ側の音の引っかかりでした。
  - チップ自身の符号化→復号との mel スペクトル距離は、日本語 2.68〜2.82 dB、英語 2.53〜2.67 dB です。
- **3 つの版**（同じアルゴリズム、同じ API）：

  | 版 | ビルド | 用途 | 状態 | Apple M5 |
  |---|---|---|---|---|
  | double | `make` | 基準。numpy の参照実装とビット単位で一致 | 62 KB | 36 µs／フレーム |
  | float | `make CFLAGS="-O2 -DAMBE_ENC_FLOAT"` | 単精度 FPU 向け（double の演算・libm 呼び出しなし） | 31 KB | 36 µs |
  | **固定小数点** | `make FIXED=1` | **MCU 向けの本命**。整数演算のみ（浮動小数点・除算・libm なし） | **13 KB** | **18 µs** |

  - 固定小数点版は、チップの復号音との mel 距離で float 版との差が 0.01 dB 以内です（240 発話）。出力はどの CPU でもビット単位で同じです。
  - 実機（MCU）での速さは下の「MCU での実測」を見てください（Cortex-M7 400 MHz で CPU の約 8%、ESP32 240 MHz で約 26%）。
  - 動的メモリ確保はありません。
- **依存**：C99 だけです（double・float 版は libm の `floor`、`exp`、`frexp`、`fabs`、`fmod` も使います）。

## ビルド
```
make            # libambeenc.a、wav2ambe、テスト用プログラム
make test       # 同梱の音声で、参照実装（numpy）の出力とビット単位で一致するか確認し、速度を表示
make CFLAGS="-O2 -DAMBE_ENC_FLOAT"    # float 版（単精度 FPU の MCU 向け）
make FIXED=1    # 固定小数点版（make test FIXED=1 で、その期待値とのビット一致を確認）
```
自分のビルドに加えるソースは、`include/` と次のどちらかです。
- double / float 版：`src/encoder.c analysis.c quant.c fft.c enc_tables.c`
- 固定小数点版：`src/fx_encoder.c fx_analysis.c fx_quant.c fx_dsp.c fx_tables.c`（`-DAMBE_ENC_FIXED` は不要です）
- FEC（rate 33）を使うときは、どちらの版にも `src/fec.c` を加えます。

## 使い方
### コマンドライン
```
./wav2ambe in.wav out.ambe                   # 8 kHz・モノラル・16 ビットの WAV → 7 バイト／20 ms のフレーム列
./wav2ambe in.wav out.ambe --background      # 無音・背景雑音を背景雑音フレーム（b0 = 124）で送る（ECMODE 0x0800 相当）
./wav2ambe in.wav out.ambe --fec             # FEC 付きの 9 バイト／20 ms のフレーム列（AMBE-3000R rate 33）
../decoder/ambe2wav out.ambe out.wav         # 復号して聴く（decoder。--fec で作ったものは --rate33 を付ける）
```
入力は 8 kHz・モノラル・16 ビットの WAV です。それ以外は、先に `sox in.wav -r 8000 -c 1 -b 16 in8k.wav` などで変換してください。
既定では、有音部の平均レベルを −26 dBFS（学習時のレベル）に合わせてから符号化します。合わせたくない場合は `--no-normalize` を付けます。

### C API（`include/ambe_enc.h`）
```c
#include "ambe_enc.h"
static double mem[70000 / sizeof(double)];       /* ambe_enc_size() 以上（固定小数点版は 14 KB で足りる）、8 バイト境界 */
ambe_encoder *enc = ambe_enc_init(mem);           /* 呼び出し側のメモリに置く（malloc 不要） */
ambe_enc_set_background(enc, 1);                  /* 任意：背景雑音モード（ECMODE 0x0800 相当、既定はオフ） */
uint8_t frame[7];
if (ambe_enc_push(enc, pcm160, frame)) { /* 1 フレームできた（ひとつ前のチャンクの分） */ }
if (ambe_enc_flush(enc, frame)) { /* ストリームの最後のフレーム */ }
ambe_enc_to_ambe_d(frame, bits49);                /* mbelib / DSD / blip25c の ambe_d 順が欲しいとき */
ambe_enc_background_frame(gain, frame);           /* 背景雑音（b0 = 124）フレーム。gain = 1 で DMR の無音フレーム */
ambe_enc_to_rate33(frame, frame9);                /* FEC をかけて 9 バイトの rate 33（3600x2450）に */
ambe_enc_bits_to_rate33(bits49, frame9);          /* ambe_d 順の 49 ビットから rate 33 に */
```
- 入力は 8 kHz・int16・160 サンプルずつです。
- 出力は AMBE-3000R の rate 34 と同じビット順の 7 バイトです（`blip25_decode_2450_thumbdv` でそのまま復号できます）。
- ピッチを 1 フレーム先まで見て決めるため、`ambe_enc_push` は**ひとつ前**のチャンクのフレームを返します（最初の呼び出しは 0）。N チャンク入れると N フレーム出ます。
- 解析窓は過去側にあり、遅延はチップ自身とほぼ同じです。
- 学習時の入力レベルは −26 dBFS 前後です。極端に小さい・大きい入力は、合わせてから渡してください。
- 1 つの `ambe_encoder` は 1 本のストリーム専用です。

### FEC（rate 33、`src/fec.c`）
`ambe_enc_to_rate33` は、7 バイトのフレームに AMBE-3000R の rate 33（3600x2450）と同じ FEC をかけて、9 バイトにします。デコーダの `blip25_fec_3600` のちょうど逆です。
- 49 ビットを u0（12）・u1（12）・u2（11）・u3（14）に分けます。
- c0 は u0 の拡張 Golay [24,12] 符号です（3 ビットまで訂正、4 ビットを検出）。
- c1 は u1 の Golay [23,12] 符号（3 ビットまで訂正）に、u0 を種とする PN 系列を XOR したものです。
- c2 = u2、c3 = u3 で、保護はありません。
- 72 ビット（36 ディビット）を P25 Phase 2 の Annex S の順に並べます。
- 整数演算だけで、3 つの版（double・float・固定小数点）で共通です。

`make test` の `tests/fec_test` で、次のことを確かめています。
- **チップとの一致**：DMR の無音フレームと、下の「無音フレームの仕様」に載せたチップの実測 4 フレームが、チップの rate 33 出力とビット単位で一致します。
  チップの rate 33 出力（`../decoder/tests/vectors/chip3600.bin`、3059 フレーム）を FEC でほどいて符号化し直すと、すべて元と一致します。
- **符号の性質**：u0・u1 の 4096 通りすべてで、c0・c1 の重み分布が拡張 Golay [24,12]（最小距離 8）・Golay [23,12]（最小距離 7）の理論値どおりです。
- **誤り訂正**：40 フレームのそれぞれで、c0・c1 の 1〜3 ビット誤りのすべてのパターンを訂正し（硬判定・軟判定）、c0 の 4 ビット誤りのすべてのパターン（10626 通り）を検出します。
  c0・c1 に同時に誤りがあっても訂正され、c2・c3 の誤りはそのまま残ります（保護なし）。
- 72 ビット内の位置は、Annex S の表ではなく mbelib（pyambelib）の `rW/rX/rY/rZ` 表から求めています。

## 仕組み
1 フレームにつき、過去の入力の 512 点パワースペクトルを 4 本だけ計算し、すべての段で使い回します。
4 本の窓は、振幅解析用の学習済み 400 タップ窓と、200・256・384 サンプルのハン窓です。
- **ピッチ（b0）**：120 候補それぞれについて、各スペクトルの調波の位置にあるエネルギーの割合と、対数スペクトル上での盛り上がりを求めます。1/2・2・2/3・3/2 倍の周期のものも使います。線形の採点で 8 候補に絞り（16 候補と品質は同じでした）、小さな MLP（隠れ層 48）で採点し、1 フレーム先読みの Viterbi（L1 距離変換）で決めます。
- **有声/無声（b1）**：帯域ごとの調波の山谷比、調波付近のエネルギーの割合、帯域エネルギー、雑音フロアからの高さ、ピッチの確からしさを求めます。フレーム t−2・t−1・t（確定ピッチ）と t+1（その時点の暫定ピッチ）を並べ、小さな MLP（約 1.1 万パラメータ）で 32 符号から選びます。
- **振幅**：同じスペクトルから調波ごとの帯域エネルギーを求め、学習済みのレベル補正をかけます。
- **量子化**：仕様どおりです（予測係数 0.65 の閉ループ、ゲイン・PRBA・HOC の最近傍探索）。仕様テーブルは、チップの実測で 4 か所修正したものを使っています。

定数（モデルの重みを含む）は `src/enc_tables.c` にあります。研究用リポジトリ neural-ambe2 の学習結果（`lite/models.json`、`ambe2450/tables.json`）から、そちらの `ambe-enc/tools/gen_tables.py` で生成したものです。
numpy の参照実装は neural-ambe2 の `lite/lite_encoder.py` です。C 版とはビット単位で一致します。float 版は 20000 フレーム中 99.9% のフレームが一致し、違いはほぼ同点の箇所で生じる数フレームの揺れです。

## 固定小数点版（MCU 向け）
`src/fx_*.c` です。double 版と同じ処理を、整数演算だけで書いています。浮動小数点と libm は使いません。除算はフレームあたり数十回だけで、ビンごとのループにはありません。
- **数値の形式**：
  - スペクトルは log2(P + 1) を Q8 の int16 で持ちます。線形のパワーが要るところは表引きの exp2 で戻します（誤差 0.3%）。
  - FFT は 32 ビットです。入力の大きさから桁を決めるので、段ごとのスケーリングなしであふれません。回転因子は Q15 です。
  - MLP は 12 ビットの重み（行ごとのスケール）と Q8 の入力で、累算は 32 ビットであふれないことを保証しています。
  - 量子化器は log2 領域の Q16 です。
- **CPU ごとの最適化**（結果はどれもビット単位で同じ）：
  - ARM の DSP 拡張（Cortex-M4/M7/M33）では、16 ビット 2 並列の積和命令（SMLAD）を使います。
  - 32×32→64 ビットの掛け算命令がない Cortex-M0/M0+ では、32 ビットの掛け算 2 回で同じ値を計算します。
  - CLZ 命令がない CPU では、表引きで代わりにします。
- 定数表（`src/fx_tables.c`、約 70 KB）は、研究用リポジトリの `ambe-enc/tools/gen_fx_tables.py` で作ります。
- テスト用の期待値（`tests/vectors/*.fixed.*`）は固定小数点版自身の出力です。各 MCU で同じビット列が出ることを確かめるのに使います。

### MCU での実測
同梱の雑音入りの音声（`tests/vectors/noisy.pcm`、LibriSpeech の発話に白色雑音を SNR 3.5 dB で加えたもの、248 フレーム）を符号化し、出力が期待値とビット単位で一致すること、1 フレーム（20 ms）あたりの時間を測りました。デコーダ（`../decoder`、blip25c）も同時に測っています。

**実機**（サイクルカウンタで実測。どれも全フレームが期待値と一致）：

| ボード | 版 | エンコード | デコード（rate 34／rate 33） | エンコード＋デコード |
|---|---|---|---|---|
| Arduino Portenta H7（Cortex-M7, 400 MHz） | 固定小数点 | 64 万サイクル = 1.6 ms（8%） | 0.81 ms／0.82 ms | 約 2.4 ms（12%） |
| 同上 | float | 140 万サイクル = 3.5 ms（18%） | — | — |
| ESP32-WROOM-32（240 MHz）、コードと表を RAM に配置 | 固定小数点 | 128 万サイクル = 5.3 ms（27%） | 2.0 ms／2.1 ms | 約 7.4 ms（1 コアの 37%） |
| 同上、フラッシュのまま | 固定小数点 | 367 万サイクル = 15.3 ms（77%） | 3.0 ms／3.1 ms | 約 18 ms（実用外） |
| 同上、フラッシュのまま | float | 432 万サイクル = 18.0 ms（90%） | — | — |

- 背景雑音モードでは、エンコードが 3〜7% 重くなります（RAM 配置の場合。フラッシュのままでは 30% 以上重くなります）。
- **ESP32 ではコードと定数表を RAM に置いてください**。フラッシュのままでは、キャッシュ（32 KB）に収まらず約 3 倍遅くなります。
  - ESP-IDF では、リンカ設定（`examples/esp32/main/ambe_enc_ram.lf` のような `noflash` 指定）だけで、ソースを変えずに置けます。
  - 固定小数点版の表は約 70 KB で収まります。float 版は約 18 万バイトで、ESP32 の DRAM に収まりません。
- ESP32 はデュアルコアなので、エンコーダとデコーダを別のコアで動かすこともできます。

**エミュレータ**（QEMU、実行命令数。サイクル数ではありません。どれも全フレームが期待値と一致）：

| CPU | 命令数／フレーム（固定小数点版） |
|---|---|
| Cortex-M4 / M7 | 約 63 万 |
| Cortex-M3 | 約 74 万 |
| RISC-V RV32IMC（FPU なし） | 約 98 万 |
| ESP32 / ESP32-S3（Xtensa） | 約 100 万 |

### テストの動かし方（`tests/mcu/`）
共通のテスト本体は `mcu_test.c`（エンコーダ）と `dec_test.c`（デコーダ）です。各環境の実行スクリプトがビルド・書き込み・結果の表示までします。
```
tests/mcu/arm/run_arm.sh m0|m3|m4|m7 fixed|float|double          # QEMU の MPS2 ボード（arm-none-eabi-gcc と qemu-system-arm）
tests/mcu/riscv/run_riscv.sh rv32imc fixed                        # QEMU の virt ボード（riscv32 の gcc と qemu-system-riscv32）
tests/mcu/run_esp.sh esp32|esp32s3|esp32c3 fixed|float            # ESP-IDF＋Espressif QEMU（examples/esp32 のアプリ）
ESPPORT=/dev/cu.usbserial-XXXX AMBE_ENC_RAM=1 tests/mcu/run_esp.sh esp32 fixed     # ESP32 の実機（RAM 配置）
tests/mcu/portenta/run_portenta.sh fixed|float                    # Portenta H7 の実機（arduino-cli、arduino:mbed_portenta）
```
- 3 つ目の引数に `-DFX_PROFILE`（ESP では `profile`）を付けると、固定小数点版の段ごとの時間も表示します。
- QEMU の結果は命令数の目安です。キャッシュや待ちサイクルは反映されません。
- ESP32-C3 の Espressif QEMU は、命令数を数えるモード（`-icount`）では起動しませんでした。RV32IMC の命令数は、標準 QEMU の virt ボードで測っています。

## 無音フレームの仕様（AMBE-3000R の実測）
AMBE-3000R（ThumbDV, ファームウェア `V120.E100.XXXX.C106.G514.R009.B0010411.C0020208`）で調べた、無音に関わるフレームの扱いです。
特に断りのない値はすべて実測です。推測には「推測」と書いています。

このエンコーダでの再現については、節の最後の「このエンコーダでの扱い」を見てください。

### 記法
- フレームは 49 ビットです。`ambe_d` 順は、mbelib・DSD・blip25 の並びです。
- 各符号のビット位置（`ambe_d` の添字、上位ビットから）：

  | 符号 | 幅 | `ambe_d` の位置 |
  |---|---|---|
  | b0（ピッチ） | 7 | 0, 1, 2, 3, 37, 38, 39 |
  | b1（有声/無声） | 5 | 4, 5, 6, 7, 35 |
  | b2（ゲイン） | 5 | 8, 9, 10, 11, 36 |
  | b3（PRBA24） | 9 | 12–19, 43 |
  | b4（PRBA58） | 7 | 20–23, 40, 41, 42 |
  | b5〜b8（HOC） | 5, 4, 4, 3 | 24–27, 44 / 28–30, 45 / 31–33, 46 / 34, 47, 48 |
- rate 34（FEC なし 7 バイト）の生ビット順では、i 番目のビットが `ambe_d[R[i]]` です。
  R = 0 18 36 1 19 37 2 20 38 3 21 39 4 22 40 5 23 41 6 24 42 7 25 43 8 26 44 9 27 45 10 28 46 11 29 47 12 30 48 13 31 14 32 15 33 16 34 17 35
- rate 33（3600x2450、FEC 付き 9 バイト）は、同じ 49 ビットを Golay 符号と PN 変調で包み、P25 Phase 2 の Annex S で並べたものです（`../decoder` の `blip25_fec_3600` でほどけます）。

### 1. エンコーダの既定動作（ECMODE = 0x0000）
**出る条件**：解析窓の中の信号が、直流分を除いてちょうどゼロのとき。
- 全サンプル 0 の入力だけでなく、**どんな大きさの一定値（直流）**でも同じになります（1、2、8、64、1024、8192、−1、−8 で確認）。入口で直流を除いているためと推測しています。
- 交流成分がわずかでもあれば出ません。±1 LSB のランダム、0/1 のランダム、RMS 1 の雑音、20 ms ごとの 1 サンプルのインパルスでは、通常のフレームになります。
- ±1 の交互（ナイキスト周波数）では b2 = 0 になりますが、b0 = 105 の別のフレームになります。

**中身**：

| 符号 | 値 |
|---|---|
| b0 | 119（最も低いピッチ。規格の特別符号ではなく、通常の範囲 0〜119 の端） |
| b1 | 16（全帯域無声） |
| b2 | 0（最小ゲイン） |
| b6 | 14 |
| b3, b4, b5, b7, b8 | フレームごとに変わる。観測した値の範囲は b3 ∈ {86, 87, 90, 91, 308}、b4 ∈ {27, 36, 78}、b5 ∈ {2, 8}、b7 ∈ {1, 3, 13}、b8 ∈ {1, 3, 5, 7} |

- **再現性**：リセット直後から無音を入れた場合の出力は、毎回ビット単位で同じです。
- **b3〜b8 が揺れる理由**：仕様どおりの予測付き閉ループ量子化器で、目標振幅を十分低い一定値（log2 振幅 −8 以下）にすると、1/3 のフレームがビット単位で再現できます。目標が一定だと平均を引いた形は値によらないので、b3〜b8 は前フレームの復号値からの予測を打ち消そうとする値になります。乱数ではなく、量子化器の状態で決まる決定的な値です。残りが合わないのは、チップの符号帳探索が単純な最近傍探索と細部で違うためと推測しています。
- **リセット直後の 2 フレーム**は b0 = 76 です（それ以外は同じ形）。
- **リセット直後からの実例**（rate 34 の生ビット順 ｜ `ambe_d` 順 ｜ b0..b8）：

  | フレーム | rate 34（16 進） | ambe_d（16 進） | b0..b8 |
  |---|---|---|---|
  | 0 | `cd4ac301b6e600` | `9802b94fa4d380` | 76 16 0 87 78 8 14 13 7 |
  | 1 | `8d4ac009a64d00` | `9802d91e44c280` | 76 16 0 90 78 2 14 3 1 |
  | 2 | `deba0301a6e600` | `e802b44fa79280` | 119 16 0 87 36 8 14 13 5 |
  | 3 | `9f9ac301a64500` | `e802d94e07d280` | 119 16 0 91 78 8 14 1 1 |
  | 4 | `de9cc909b6e600` | `e802b31fa77380` | 119 16 0 87 27 2 14 13 7 |
  | 5 | `df9ac201a64c00` | `e802b94e47c280` | 119 16 0 86 78 8 14 3 1 |
  | 6 | `9f9ac301a6e700` | `e802d94fa7d280` | 119 16 0 91 78 8 14 13 5 |
  | 7 | `deba0109b6e600` | `e802b41fa79380` | 119 16 0 87 36 2 14 13 7 |

- **rate 33** でも、FEC をほどいた 49 ビットは rate 34 と全フレーム同じです（FEC の誤り 0）。リセット直後の rate 33 出力は `954be6500310b00777`、`a478e4520114c02767`、`fdc5825757247cc3af`、`eec4a07775103c87ab`、… です。
- **音声 → 無音の切り替わり**：
  - ゲイン（b2）は約 1 フレームで 0 になります。
  - b0 は 119 になる前の 1〜3 フレーム、別の値（直前のピッチや 110 前後の値）をとります。
  - 境目のフレームが b0 = 0、b1 = 18〜29（L = 56 の特別な格子の範囲）になることがあります。
  - 切り替え位置を 16 サンプル刻みでずらすと、最初の完全な無音フレーム（b0 = 119）までは 0〜6 フレームで、ばらつきます。
- **無音 → 音声の切り替わり**：音が入った最初のフレームから通常の符号に戻ります。境目の b1 が L = 56 の符号（22〜31）になることがあります。
- **チップの復号器で再生すると**、2〜3 フレームで音量が下がり、そのあとは**完全なゼロ**（全サンプル 0）になります。

### 2. ECMODE の無音関連ビット（エンコーダ）
ECMODE の 16 ビットを 1 ビットずつ立てて、無音、微小な雑音、音声を符号化しました。ビットの正式名は確認していません（DVSI の資料は参照していません）。

| ECMODE | 動作 |
|---|---|
| 0x0000（既定） | 上の 1. のとおり。b0 ≥ 120 は一切出ない |
| **0x0800** | **無音・定常的な雑音を「背景雑音フレーム」（b0 = 124、b1 = 16）にする**。下記参照 |
| **0x4000** | 入力に関係なく**全フレームが b0 = 122（消失）**になる（ミュート相当と推測） |
| 0x0040 | b0 = 119 の無音フレームが増える（雑音抑圧と推測） |
| その他 | 無音の出力に変化なし |

**ECMODE 0x0800 の背景雑音フレーム**：
- **形**：b0 = 124（125 は出ない）、b1 = 16、**b2 = 背景雑音の大きさ**、b3〜b8 = 雑音のスペクトルの形で、フレームごとに変わります。
- 2 回の測定（異なる雑音）の値をまとめています。
- **完全な無音でも b2 = 5** になります（リセット直後から b0 = 76 の 2 フレームもなく、最初から 124）。例：`f74ac1432ea100`（ambe_d `f828692f8cd080`、b0..b8 = 124 16 5 269 78 4 14 12 1）。
- **白色雑音の RMS と b2 の関係**（リセット直後から、定常状態）：

  | RMS（LSB） | 1 | 2 | 4 | 6 | 8 | 10 | 12 | 16 | 20 | 24〜28 | 32 | 40〜64 |
  |---|---|---|---|---|---|---|---|---|---|---|---|---|
  | b2 | 5–6 | 7–9 | 14–19 | 20–23 | 24–25 | 25–27 | 26–28 | 28–29 | 29–30 | 30 | 30–31 | 31 |

- **判定**：リセット直後からなら、定常的な雑音は RMS 64（約 −54 dBFS）でも背景雑音と判定されました。音声の中の静かな部分も置き換わります（ある 3.6 秒の発話で 179 フレーム中 43）。音声のあとに大きめの雑音（RMS 30）が続く場合は、ほとんど置き換わりませんでした。判定は入力に追従して変わるようです。
- **発話での統計**（JSUT・LibriSpeech の 220 発話、約 64000 フレーム。−26 dBFS 前後の音声に、白色・ピンク・低域の雑音を SNR 0〜30 dB で加えたものと、加えないもの。各発話をリセット直後から符号化）：
  - 背景雑音フレームになった割合：雑音なし 16%、白色 32%、ピンク 29%、低域 22%。
  - b1 は 11119 フレームすべてで 16 でした。b0 = 125 や、ほかの b0 ≥ 120 は出ませんでした。
  - 連続する背景雑音フレームの長さは、中央値 3 フレーム（10% 点 1、90% 点 21）です。1 フレームだけのものが 21% あります。音声と背景の切り替わりは毎秒約 3.4 回です。
  - **b2 は区間の中でほぼ一定**です（隣り合う背景雑音フレームで b2 が同じ割合 90%）。b3〜b8 は 70% のフレームで前と変わります。
  - **リセット直後の最初の区間**は、雑音があると b2 = 31 になります。雑音がないときは、その時点の入力のレベルに応じて 2〜8 です。
  - **b2 と雑音のレベル**：大きくなるほど b2 も大きくなりますが、圧縮されています。たとえば白色雑音 −56 dBFS で b2 = 25、−40 dBFS で 30、−31 dBFS で 31 です（いずれも発話ごとの中央値）。つまり、チップで復号した背景雑音は、元の雑音よりかなり小さくなります（−40 dBFS の雑音が −64.5 dBFS になる）。
  - **予測の状態**：背景雑音フレームは、量子化器の予測（前フレームの振幅とゲイン）を更新しません。背景雑音区間の直後の音声フレームの b2 は、区間の直前の音声フレームの状態から予測すると、通常のフレームと同じ割合（約 53%）で再現できます。状態を初期化したとみなすと 10% しか合いません。

### 3. 復号器の扱い（AMBE-3000R の復号器。rate 34 で測定し、DMR の無音フレームは rate 33 でも同じ結果）
| 受信したフレーム | 復号器の動作 |
|---|---|
| b0 = 0〜119 | 通常の音声フレーム。上の 1. の無音フレーム（b2 = 0）は完全なゼロになる |
| **b0 ∈ {124, 125} かつ b1 ∈ 16〜23** | **背景雑音（無音）フレーム**：大きさは b2 で決まる（b3〜b8 でもわずかに変わる）。b2 = 0 なら完全なゼロ。中身は無声の雑音で、スペクトルの形は b3〜b8 で決まる（下記） |
| それ以外の b0 = 120〜127（b1 が 16〜23 でない 124・125 を含む） | **消失**：直前のフレームを 3 回繰り返し、4 回目で弱め、5 回目から無音（約 −95 dBFS） |
| トーンフレーム（û0 の上位 6 ビットが 0x3F、û3 の下位 4 ビットが 0） | トーン。ただし ID 255 は消失と同じ扱い |

- 背景雑音フレームの条件は、DMR の無音フレームの 1 ビット反転試験と、b0 ∈ {124, 125} × b1 = 0〜31 の全組み合わせで確認しました（b1 = 16〜23 のときだけ背景雑音、ほかはすべて消失）。
- **背景雑音フレームの出力レベルと b2 の関係**（b0 = 124、b1 = 16、b3..b8 = 52 79 18 14 12 1、リセット直後からの定常値、dBFS）：

  | b2 | 0 | 1 | 2 | 4 | 8 | 12 | 16 | 20 | 24 | 28 | 30 | 31 |
  |---|---|---|---|---|---|---|---|---|---|---|---|---|
  | dBFS | −∞（全サンプル 0） | −135.7 | −95.6 | −92.4 | −84.3 | −81.1 | −78.6 | −75.7 | −73.0 | −68.8 | −64.5 | −57.9 |

- **背景雑音フレームのスペクトルの形**：b2 = 31 に固定し、チップのエンコーダが出した背景雑音フレーム 60 個と、b3・b4 を単独で動かしたフレームを、それぞれ 25 回繰り返して復号しました。
  - 出力のレベルは形によらずほぼ一定です（b2 = 31 で約 −58 dBFS。形によって −52 dBFS 程度まで）。
  - b3（PRBA24）を変えると、500 Hz 帯ごとのレベルが最大 20 dB ほど変わります。b4（PRBA58）の影響は最大 5 dB 程度です。
  - 出力のスペクトルは、b3〜b8 を予測なしで復号した振幅を **L ≈ 15 本の調波（基本周波数 約 250 Hz）**の格子に置いたものと最もよく合います（相関 0.74。L = 14〜16 でほぼ同じ、L = 43 では 0.63）。
- **DMR の無音フレーム**：
  - rate 33（9 バイト）は `B9 E8 81 52 61 73 00 2A 6B` で、FEC の誤りなしで復号できます。
  - ambe_d 順では `F8 01 A9 9F 8C E0 80`、rate 34 の生ビット順では `f74ad80926b400` です。
  - 符号は b0..b8 = 124 16 1 52 79 18 14 12 1 で、b2 = 1 の背景雑音フレームです。チップの復号器では約 −136 dBFS、つまり事実上の無音になります。
  - ただし、チップのエンコーダは既定の設定ではこのフレームを出しません。
- **他の実装との違い**：
  - mbelib は b0 = 124・125 を、b1 に関係なく無音フレーム（ピッチ 2π/32、L = 14、全帯域無声）として扱います。
  - blip25-vocoder（`../decoder`）は、b0 = 120〜127 でも、DMR の無音フレームと同じ下位のビットなら背景雑音として扱います。チップは 124・125 以外を消失として扱うので、ここだけ食い違います。
  - 音量の推移は、ここに挙げた試験ではチップと blip25 で一致しました（サンプル単位では一致しません）。

### このエンコーダでの扱い
- **デジタル無音（一定値の入力）**は、チップの既定動作と同じ形にします。
  - **判定**：フレームの解析範囲（フレーム先頭から −472〜−9 サンプル）のサンプルがすべて同じ値なら無音です。
  - **出力**：b0 = 119、b1 = 16 とし、振幅の目標を一定の低い値にして量子化します。b2 = 0 で、b3〜b8 は閉ループ量子化器が決めます。
  - **チップとの一致**：完全な無音を入れると、b0・b1・b2・b6 は 100% 一致します。b3〜b8 はフィールドごとに 16〜53% の一致で、値はチップが出す値の集合に収まります。
  - **復号結果**：チップの復号器で鳴らすと、チップ自身の無音フレームと同じく完全なゼロになります。
  - **違い**：チップのリセット直後の 2 フレーム（b0 = 76）はまねていません。
- **背景雑音モード**（`ambe_enc_set_background(enc, 1)`、`wav2ambe --background`。既定はオフ）：ECMODE 0x0800 をまねて、無音・背景雑音の区間を背景雑音フレームで送ります。
  - **判定（VAD）**：有声/無声の判定と同じ特徴量（フレーム t−2〜t+1）に、過去 10・50 フレームのレベルの最小値と、開始からのフレーム数を加え、小さな MLP（隠れ層 32 × 2）で判定します。チップの ECMODE 0x0800 の出力（上記の 220 発話のうち 160 発話）を教師に学習しました。
  - **出力**：b0 = 124、b1 = 16 です。
    - b2：同じ入力の別の MLP で、チップの b2 を回帰します。
    - b3〜b8：16 帯域の対数エネルギー（そのフレームと前のフレーム）から、チップの背景雑音フレームを復号した形（15 本の調波）を線形に予測し、予測なしで量子化します。
    - 量子化器の予測の状態は、チップと同じく更新しません。
  - **チップとの比較**（学習に使っていない 60 発話）：
    - フレームの判定の一致は 92%（適合率 91%、再現率 78%）です。
    - b2 の一致は 24%、±1 以内は 54% です。
    - b3〜b8 の形は、チップの形との差が 2.8 dB です（チップの平均的な形を常に使うと 3.1 dB）。
  - **チップの復号器で鳴らした比較**（30 発話）：
    - 両方が背景雑音とした区間の出力レベルは、平均で一致しました（どちらも −59.5 dBFS、フレームごとの差は平均 3.5 dB）。
    - 音声のフレームの出力は、このモードを使わない場合と平均 0.4 dB しか違いません。
  - **違い**：
    - 背景雑音と判定する割合が、チップよりやや少なめです（24.5% 対 28.2%）。
    - 1 フレームだけの背景雑音区間が多めで（35% 対 21%）、切り替わりが毎秒約 4.3 回とチップ（3.4 回）より多くなります。
    - 速度はほぼ変わりません（Apple M5 で 1 フレームあたり 1 µs 未満の増加）。
  - **デジタル無音**もこのモードでは背景雑音フレームになります。b2 は 5〜7 です（チップは 5）。
  - **発話を含まない定常雑音**（学習データにない条件）では、b2 が小さめに出ます。たとえば RMS 32 の白色雑音だけを入れると、チップは 30〜31、このエンコーダは主に 24〜27 です（チップの復号で約 −64 dBFS に対して約 −72 dBFS）。
- **背景雑音フレームを直接作る関数**：
  - `ambe_enc_background_frame(gain, out)`：大きさ b2 = gain の背景雑音フレームを作ります。スペクトルの形は DMR の無音フレームと同じです。
  - `AMBE_ENC_DMR_SILENCE_RATE34` / `_AMBE_D` / `_RATE33`：DMR の無音フレームそのものです。`ambe_enc_background_frame(1, …)` と同じフレームです。
