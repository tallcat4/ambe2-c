# AMBE+ デコーダ — AMBE-3000R の AMBE-2000 互換レート

> このページのコマンドは `decoder/` ディレクトリで実行します。

AMBE-3000R(ThumbDV)の AMBE+(AMBE-2000 系)のレートを復号します。対応しているのは次の 5 レートです。

| RATET | 合計 | 音声 | FEC | フレーム | 関数 |
|---|---|---|---|---|---|
| 31 | 2000 | 2000 | なし | 40 ビット(5 バイト) | `blip25_decode_ambeplus_r31` |
| 0 | 2400 | 2400 | なし | 48 ビット(6 バイト) | `blip25_decode_ambeplus_r0` |
| 22 | 4000 | 2400 | 1600 | 80 ビット(10 バイト) | `blip25_decode_ambeplus_r22` |
| 17 | 4000 | 4000 | なし | 80 ビット(10 バイト) | `blip25_decode_ambeplus_r17` |
| 26 | 6400 | 4000 | 2400 | 128 ビット(16 バイト) | `blip25_decode_ambeplus_r26` |

- 2400 bps の音声ビットは、D-STAR の音声ビットと同じものです(FEC だけが違います)。
- これらのレートの仕様は公開されていません。ここに書いたことは、すべて ThumbDV を相手にした計測と、失効した DVSI の特許から割り出したものです。

## 使い方
```
./ambe2wav in.ambe out.wav --rate 22    # RATET 22 のフレーム列(10 バイト/20 ms、MSB 先頭)→ 8 kHz WAV
```
`--rate` には 34、33、31、0、22、17、26 を指定できます。

C からは次のように使います。
```c
#include "blip25.h"

blip25_decoder dec;
int16_t pcm[160];
int errors;
blip25_init(&dec);
blip25_decode_ambeplus_r22(&dec, frame10, pcm, &errors);  /* errors: 畳み込み符号で訂正したビット数 */
```

| 関数 | 内容 |
|---|---|
| `blip25_fec_ambeplus_r22` / `_r26` | FEC だけを外し、音声ビット(48 / 80)を返す。戻り値は訂正したビット数 |
| `blip25_fec_ambeplus_r22_soft` / `_r26_soft` | 軟判定版(LLR: 正なら 1、絶対値が信頼度) |
| `blip25_decode_ambeplus2400` / `4000` | 音声ビット(チップの直列順)から復号する |

## 品質
チップ自身の復号音との差(mel スペクトル距離)を、日本語(JSUT)と英語(LibriSpeech)それぞれ 20 発話で測りました。

| レート | 平均 | JSUT | LibriSpeech |
|---|---|---|---|
| 2000(31) | 1.19 dB | 1.43 dB | 0.95 dB |
| 2400(0、22) | 1.24 dB | 1.50 dB | 0.99 dB |
| 4000(17、26) | 2.19 dB | 2.42 dB | 1.97 dB |

参考として、AMBE+2 2450 のデコーダは 0.77 dB、mbelib の D-STAR デコーダをこのビット列に使うと約 8.7 dB です。

## しくみ
### FEC(RATET 22、26)
- 音声ビットの先頭 n ビット(22 は 20 ビット、26 は 36 ビット)を、拘束長 7、レート 1/2 の畳み込み符号(生成多項式 171、133(8 進))で符号化します。末尾に 0 を 6 ビット付けて終端します。
- 残りの音声ビットは、そのまま後ろに付けます。
- この列を 12 行の行列に列方向に書き込み、行方向に読み出します。行の長さは N/12 で、割り切れない分は先頭の行が 1 ビット長くなります。
- FEC のないレート(0、17、31)も、同じインターリーブで音声ビットを並べています。
- 復号は Viterbi(硬判定・軟判定)です。チップの FEC なしレートのビットと、全フレームで一致することを確かめています。

### 音声パラメータ
どのレートも、同じパラメータを運びます。ピッチ b0、有声/無声 b1、ゲイン b2、PRBA ベクトル b3(G2〜G4)と b4(G5〜G8)、4 ブロック分の HOC ベクトル b5〜b8 です。合成には blip25 のエンジンをそのまま使い、逆量子化を AMBE+ 用に差し替えています(`src/ambeplus.c`)。

- **2400 bps**
  - 符号帳は mbelib(ISC)の D-STAR 用と同じです。
  - ピッチは f0 = 8000 · 2^(−4.258322 − 0.021770 b0) Hz で、L = ⌊0.4627 / f0⌋ です(f0 は 1 サンプルあたりのサイクル数)。mbelib の値は推測で、最大 4.5% ずれていました。
  - 予測係数は ρ = 0.8 です(AMBE+2 は 0.65)。
  - ゲインは前フレームから予測しない絶対値で、表はチップで測りました。
- **2000 bps**
  - 2400 bps の各フィールドから最下位ビットを 1 本ずつ落としたものです(b1 だけは落としません。8 ビット減って 40 ビット)。
  - ベクトルは 2400 bps の符号帳の偶数番目を使います。ピッチとゲインは、2400 bps の隣り合う 2 つの値の中間になります。
- **4000 bps**
  - PRBA とゲインの符号帳は 2400 bps と共通です。HOC は 5 ビットずつで独自の符号帳を持ちます(チップの復号音に合わせて推定した値)。
  - 有声/無声は 6 帯域のフラグです(50〜55 番)。L は ⌊0.4725 / f0⌋ で、約 3780 Hz まで合成します。
  - 前半の半フレームに対する補正が 2 つあり、どちらも次フレームの予測には入りません(US 6,377,916 の構成と同じ)。
    - 補間の重み(38、39 番)
    - 第 2 段の量子化(40〜49 番): ゲイン項と、スペクトル誤差の DCT 係数のベクトル量子化
  - 66〜78 番の 13 ビット(状態によって意味が変わる適応的な段とみられる)は、まだ復号していません。4000 bps の品質が他より劣る主な原因です。

## まだ対応していないもの
- b0 ≥ 124 のフレーム(トーン、無音、消失)。今はフレーム繰り返しとして扱います。
- 4000 bps の 66〜78 番のビット。
- FEC の誤り数に応じたフレーム繰り返しやミュート(チップの DATA_INVALID 相当)。

## 検証
`make test` に AMBE+ のテストも入っています(`tests/vectors/ap_*.bin`、LibriSpeech の 1 発話)。

| テスト | 内容 |
|---|---|
| `apfec22` / `apfec26` | FEC を外した音声ビットが、チップの FEC なしレート(0 / 17)のビットと一致する。誤り 2% のベクトルでは、Python 版の Viterbi と一致する |
| `apdec*` | 復号音が、以前の出力と一致する(回帰テスト) |

計測と当てはめのスクリプトは、研究用リポジトリ neural-ambe2 の `ambeplus/` と `scripts/collect_rates.py`、`scripts/probe_rate_decoder.py` にあります。
